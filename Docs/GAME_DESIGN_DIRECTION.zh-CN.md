# 3DPlayDemo 当前策划方向案

更新时间：2026-08-20

## 1. 项目定位

暂定名：**霓虹回收协议**。

一款第三人称都市异常题材动作 Roguelite。玩家进入被异常能源污染的封锁区，在短时高密度战斗中完成回收任务，通过装备、主动道具和局内强化形成构筑，击败区域 Boss 后继续深入。

目标体验：

- 单个房间 30–60 秒，持续提供明确目标和战斗反馈。
- 一局由战斗、机制、精英、奖励、商店和 Boss 构成。
- 画面首先保证敌我识别、攻击预警和交互物辨识，再增加装饰密度。
- 优先复用项目已有城市、工业、自然、科幻 UI 和 VFX 素材，避免继续堆放无主题的临时模型。

## 2. 核心循环

```text
选择区域
  → 普通战斗房
  → 场地机制房
  → 精英战斗房
  → 三选一奖励
  → 战地商店 / 整备
  → 区域 Boss
  → 结算与永久解锁
```

局内成长由三条线组成：

1. 装备：提供稳定属性、套装与词条。
2. 主动道具：提供有冷却的战术能力和组合反应。
3. 房间奖励：提供本局生效的强化、资源或风险交换。

## 3. 战斗设计

### 基础操作

- 移动、普通攻击、闪避、交互和主动道具构成首个可交付版本。
- 后续加入锁定目标、完美闪避、韧性与破防，但不在场景改造前继续扩大战斗系统。
- 敌人的威胁主要通过前摇、颜色、声音和地面预警表达，不依赖大量文字提示。

### 敌人职责

- 基础敌人：逼迫玩家保持移动，承担主要数量压力。
- 远程敌人：封锁安全位置，改变移动路线。
- 精英敌人：通过范围攻击、护盾或召唤改变房间规则。
- Boss：三阶段，每阶段新增一种行为或场地变化，而不只提高数值。

## 4. 视觉设计系统

### 识别色

| 对象 | 主色 | 用途 |
| --- | --- | --- |
| 玩家与友方反馈 | 青 / 白 | 角色轮廓、技能与可恢复资源 |
| 普通敌人 | 橙 / 红 | 攻击、伤害区和危险提示 |
| 精英与 Boss | 紫 / 深红 | 高威胁单位、阶段变化 |
| 可交互与奖励 | 金 / 黄 | 出口、宝箱、商店、任务物 |
| 环境 | 低饱和冷色 | 承托战斗信息，避免抢夺视线 |

### 镜头与构图

- 探索时镜头距离约 3.8 米，战斗时扩大到 4.5–5 米。
- 玩家屏幕高度约占 25%–30%，避免角色和大型敌人遮挡战场。
- 每个房间必须有一个远处地标、一个主路径和清楚的出口方向。

### 场景制作规则

每个关卡只使用一个主环境套件，并按“结构层、功能层、叙事层”搭建：

1. 结构层：地面、墙、门、桥、平台，保证路线和碰撞。
2. 功能层：掩体、危险区、出生点、奖励和出口，服务玩法。
3. 叙事层：灯牌、货物、管线、植被、损坏痕迹，说明地点用途。

同类装饰应组合成少量模块化预制体，禁止在运行时重复创建大量材质和零散几何体。

## 5. 现有关卡重做方向

### 训练区 / Level_Combat_001

- 定位：城市封锁区入口，负责教学和建立视觉基准。
- 调整：缩小敌人视觉比例、拉远战斗镜头、整理 HUD、统一灯光与命中反馈。
- 地标：封锁门、霓虹回收站、远处异常核心。

### 断电回廊 / Level_Combat_002

- 定位：狭长追击关，利用明暗变化引导方向。
- 调整：减少均匀走廊，加入旁路、断电区和恢复供电后的视觉变化。
- 地标：应急灯带、配电室、关闭的闸门。

### 能源中继站 / Level_EnergyRelay

- 定位：环形机制战，中继脉冲迫使玩家转换站位。
- 调整：围绕核心建立三段掩体和安全窗口，让预警与环境结构一致。
- 地标：中央中继核心、三座供能塔。

### 轨道装卸港 / Level_OrbitalCargo

- 定位：工业开阔区，电磁危险点切割战场。
- 调整：用集装箱、起重机和输送带形成清晰通道，减少空旷平面和悬浮临时图标。
- 地标：主起重机、货运舱门、悬挂货柜。

### 冷却花园 / Level_CryoGarden

- 定位：自然与工业混合区域，冰霜危险区限制移动。
- 调整：建立冻结水道、温室骨架和高低差，统一岩石、树木与冰晶比例。
- 地标：破损温室、冻结桥、冷却塔。

### 核心熔炉 / Level_Boss_001

- 定位：本阶段终局 Boss 场。
- 调整：三阶段分别改变照明、地面安全区和核心状态；Boss 外观与普通敌人彻底区分。
- 地标：熔炉核心、环形作业台、紧急排放口。

## 6. UI 方向

- 顶部只显示当前目标和 Boss 信息。
- 左侧集中生命、资源与 Buff；右侧显示追踪任务。
- 底部集中主动道具、闪避和交互状态。
- 商店、奖励选择和结算使用独立模态界面，不继续向常驻 HUD 叠加控件。
- 战斗中减少长句提示，重要状态使用图标、短标题和颜色表达。

## 7. 技术改造优先级

1. 拆分 `ProgressionRuntimeController` 与 `LevelRuntimeController` 的 UI、场景切换和流程职责。
2. 将伤害数字、粒子、投射物改为对象池，移除战斗中的高频场景查找。
3. 建立模块化场景预制体和统一关卡灯光配置，再批量改造其余关卡。
4. 将 HUD、商店、奖励、Boss 和结算拆成独立 View/Presenter。
5. 场景视觉稳定后，再增加锁定、完美闪避、韧性和破防。

## 8. 制作阶段与验收

### 阶段一：建立视觉基准

- 完成训练区的镜头、敌我比例、灯光、HUD、音效和命中反馈。
- 验收：战斗截图中玩家、敌人、危险区和出口能在一秒内区分；Console 无新增错误。

### 阶段二：模块化场景套件

- 建立城市、工业、冷却花园三套模块化组合，重做其余普通关卡。
- 验收：每关有独立轮廓和主地标，不再依赖大片空地与临时几何体填充。

### 阶段三：完整局内循环

- 接入机制房、精英房、三选一奖励、商店和 Boss 结算。
- 验收：可从 Boot 连续完成一局，不需要编辑器干预。

### 阶段四：战斗深度与性能

- 增加锁定、完美闪避、韧性、破防和对象池。
- 验收：完整流程测试通过，目标平台保持稳定帧率，战斗中无持续 GC 峰值。

## 9. 当前约束

- 保持 URP，不迁移到 Built-in 或 HDRP。
- 仓库包含第三方素材且当前为公开仓库；新增素材必须确认授权并保留许可证。
- 不再以新增零散系统代替画面与关卡打磨，先完成一个可复制的质量基准。
- UI 和场景改动必须以实际运行截图验收，代码改动至少执行对应的最小测试集。
